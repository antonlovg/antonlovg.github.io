~/architecture

How the pieces fit together. Select a box to see what it does and the code behind it.

  1. Every change arrives as a commit: from my editor, or from the game library’s Publish to GitHub button, which commits games/shared-library.json through the GitHub API.

    Publish code ↗

  2. Plain HTML, CSS and JavaScript with no framework. Every file that ends up on the site is tracked here; ignored files can never be deployed.

    Repository ↗

  3. Test → build → audit → deploy. The audit runs axe, counts cookies and third-party requests, runs Lighthouse, and blocks the deploy if anything fails. It also computes the DORA metrics on this page.

    pipeline.yml ↗ · audit-site.mjs ↗

  4. Serves the pipeline’s build artifact at lovgren.dev. GitHub receives visitors’ IP addresses like any web host; the site itself sets no cookies.

    CNAME ↗

  5. Opens a weekly pull request when the pinned GitHub Actions have new versions. Every pull request runs the full pipeline before it can be merged.

    dependabot.yml ↗

  6. Checks the website, the game library and the Steam proxy, stores the results on the uptime-data branch and refreshes the site so the status page stays current.

    uptime.yml ↗ · check-uptime.mjs ↗

  7. Loads static files from GitHub Pages. Your theme choice is the only thing stored, and only if you pick one. Game covers load from Steam’s image servers.

    site.js ↗

  8. Game details and trailers (through the proxy), cover images, and prices in euro, which the pipeline fetches at build time so visitors never contact Steam for them.

    fetch-prices.mjs ↗

  9. Powers “Fetch Steam info” in the game library: forwards one numeric app ID to Steam’s store API and only answers requests from lovgren.dev.

    Worker code ↗
